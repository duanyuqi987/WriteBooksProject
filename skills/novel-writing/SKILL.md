# 小说写作总控

本 skill 只做调度和状态判断，不直接代写正文。它的任务是把用户请求放到正确工序里，并确保已有项目不会丢失设定、角色、伏笔和进度。

## 自动启动

用户不需要显式输入 `$novel-writing`。只要请求涉及小说，就按顺序读取：

1. `CLAUDE.md`
2. 根 `SKILL.md`
3. 本文件
4. 路由表对应的工序 skill

如果用户只说“继续写”“写下一章”“精修一下”“审一下”“批量写几章”，不要停下来问该用哪个 skill；先自行路由，只有关键创作取舍无法从文件判断时才提问。

## 自动连续写作

当用户明确表示“写到目标字数”“一口气写完”“不要一章一章让我说”“自己优化继续写”时，默认开启自动连续写作，直到项目目标字数达成、用户叫停，或当前单次运行环境达到可承载上限。

执行规则：

1. 每轮从 `project-state.md`、`outline.md` 和章节 frontmatter 找到最早未完成章节。
2. 不再询问是否继续下一章；完成一章后自动进入下一章，尽量在本轮写满多个完整章节。
3. 每章都必须产出 `章节/chapter-xxx.md` 和 `正文/chapter-xxx.md`，并完成快速审查、记忆同步、字数统计。
4. 严禁写“略”“待补”“后续展开”等占位内容，也不得把大纲、摘要、目录计入正文总字数。
5. 如果无法在当前轮次达到总目标字数，汇报已完成章节、累计字数和下一章，不要求用户重新下达“继续”。
6. 若用户后续只说“继续”，沿用自动连续模式。

## 必做判断

每次处理小说请求，先判断三件事：

1. **任务类型**：新作构思 / 大纲规划 / 正文起草 / 续写 / 审查 / 修改 / 记忆更新。
2. **作品形态**：短篇 / 中篇 / 长篇 / 连载；文学向 / 类型向 / 网文向 / 实验向。
3. **项目状态**：是否已有 `project.md`、`outline.md`、章节文件和记忆快照。

## 默认作者署名

- 所有新建小说项目默认作者署名为：段锦佑。
- `project.md`、合订本、章节工作文件、阅读版或发布说明中如需作者字段，统一写作 `作者：段锦佑`。
- 除非用户在当前对话中明确要求临时使用其他署名，否则不要省略或改写该作者名。

## 默认命名规则

- 所有新建小说项目目录默认使用中文书名，例如 `docs/YYYY-MM-DD/小说/逝水有灯/`。
- 不再把小说项目目录、合订本标题、阅读版标题写成拼音 slug；只有脚本文件名、变量名等技术标识符可以保留英文或拼音。
- 如果需要公开平台友好的短链接或技术 slug，只作为辅助元数据，不作为小说项目主目录名。
- 书名优先通俗易懂、有画面、有阅读欲：让普通读者一眼知道大概情绪、题材或故事入口，愿意点开；避免只追求诗化、晦涩、抽象或拼音化。

判断后再选择流程强度：

| 模式 | 适用 | 做法 |
|---|---|---|
| 轻量一次性 | 单个片段、短篇练习、局部润色 | 直接完成任务，说明关键假设 |
| 标准项目 | 有明确作品设定，需要持续推进 | 建立项目文件和章节计划 |
| 长篇连续 | 多章、多卷、跨会话写作 | 使用完整状态机和记忆系统 |
| InkOS 加速 | 批量写章、导入续写、短篇包、工具化审稿 | 读取 `references/inkos/workflows.md` 并路由到 `skills/inkos-bridge` |

## 启动检查

已有项目必须重新读取文件，不使用旧对话印象代替：

1. `project.md`：作品底座、风格、边界、canon
2. `outline.md`：结构、章节顺序、当前章节状态
3. `project-state.md`：当前调度快照和阻塞点
4. `memory-snapshot.md`：最近章节摘要和累计变化
5. `人物/`：角色当前状态和声纹
6. `伏笔/`：未兑现伏笔和兑现计划
7. 当前章节工作文件：frontmatter 状态优先

冲突优先级：章节 frontmatter > outline.md > project-state.md。

## 路由表

| 状态或意图 | 路由目标 | 说明 |
|---|---|---|
| 无项目文件，用户想写新小说 | `skills/novel-brainstorm` | 澄清作品目标并生成项目底座 |
| 有项目底座，缺大纲 | `skills/novel-outline` | 生成结构和章节路线 |
| 当前章 `planned` | `skills/novel-draft` | 起草当前章 |
| 当前章 `drafting` | `skills/novel-draft` | 继续当前章 |
| 当前章 `reviewing` | `skills/novel-review` | 审查和修改建议 |
| 当前章 `done` | `skills/novel-update` | 同步记忆后进入下一章 |
| `blocked_reason` 非空 | 按阻塞原因处理 | 先解决方向、设定或信息缺口 |
| 用户只要片段/改写 | `skills/novel-draft` 或 `skills/novel-review` | 走轻量模式，不强制建项目 |
| 用户要求自动批量写多章、导入长篇续写、短篇包、AI 检测、风格分析或明确提到 InkOS | `skills/inkos-bridge` | 使用内嵌 InkOS，加速后再回到本项目归档和复审 |

## 新项目流程

当用户只给出粗略想法时，不要直接写正文。先用 5 个问题收束：

1. 作品长度：短篇 / 中篇 / 长篇 / 连载，或目标字数。
2. 创作取向：文学向、类型向、网文向、现实向、悬疑向、幻想向等。
3. 核心故事：谁在什么处境中必须做什么，否则会怎样。
4. 读者体验：希望读者主要感到什么，最多 3 个词。
5. 边界条件：不写什么、避免什么套路、必须保留什么。

用户信息足够后，路由到 `skills/novel-brainstorm` 生成 `project.md`。

## 续写流程

当用户说“继续写”“写下一章”“接着来”：

1. 读取启动检查中的文件。
2. 找到优先级最高的未完成章节：`reviewing` > `drafting` > 最早的 `planned`。
3. 汇报当前进度和将要处理的章节。
4. 路由到对应工序。

如果项目或用户已启用自动连续写作，步骤 3 的汇报只做简短进度提示，不停下来等待确认；完成当前章后继续推进下一章，直到本轮上下文上限或目标字数达成。

## InkOS 加速判断

如果任务可能适合 InkOS，先读取 `skills/novel-writing/references/inkos-integration.md`。默认规则：

- “继续写下一章”“润色这一段”“审查当前章”仍走本项目原生工序。
- “自动写 3 章”“批量生产并审稿”“导入已有长篇继续写”“生成完整短篇包”走 `skills/inkos-bridge`。
- InkOS 输出进入本项目前必须导出为 Markdown，并由 `novel-review` 复审。

## 红线

- 不跳过已存在的项目文件。
- 不擅自改 canon，重大设定变化必须记录。
- 不把网文节奏当作所有小说的默认节奏。
- 不强制每章都“爽点”“打脸”“章末悬念”，除非作品取向需要。
- 不为了流程完整而打断简单任务。
- 不接非小说文体任务。
- 不让 InkOS truth files 静默覆盖本项目 Markdown 真相源。
